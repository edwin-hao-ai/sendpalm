# 从邮件创建任务（设计）

日期：2026-11-10 · 状态：已实现

## 为什么

任务最初只为 AI 提取而建：设置里配好模型和 API Key，才会在邮件菜单里出现「提取任务」。
没配模型的人没有任何办法把一封邮件变成任务——只能去任务页手工新建一条，然后自己在脑子里
记住"这条是为了哪封邮件"。而 `Task.relatedMessageId` 字段、任务面板的「来源邮件」按钮、
以及 `Clip` 的"选取文本 → 保存"路径其实都已经存在，缺的只是中间那一步。

## 做法

消息「更多」菜单里加一项**新建任务**，不依赖任何模型：

- **标题**：有选中文本就用选中文本（和 Clip 一致），否则用邮件主题；截断到 200 字
- **备注**：发件人 `名字 <地址>`、收到时间、正文预览前 240 字
- **归属**：`relatedMessageId` 指向这封邮件，`relatedContactId` 指向发件人；
  `direction: mine`（自己动手建的任务，默认是"我承诺的"）
- **落地**：直接打开任务面板，让用户补截止时间/优先级——不弹中间表单，一次点击

反向也要看得见：

- 任务列表行：有来源邮件的任务前面加一个小信封图标（非交互，避免嵌套按钮）
- 阅读面板正文上方：`这封邮件的任务` chip 列表，点击打开对应任务

## 没做的事

- 不在阅读面板里内联编辑任务（任务面板已经是编辑器）
- 不给"对方承诺的"自动判断（AI 提取那条路已经会判断方向；手动建的任务由人来定）
- 不与"跟进提醒"合并：跟进提醒是"等对方回"，任务是"我要做"，两者都会出现在任务面板
  但不能互相替代

## 验证

`e2e/task-from-message.spec.ts`：打开邮件 → 更多 → 新建任务 → 任务面板标题即邮件主题 →
任务页出现该任务且带来源标记 → 点「来源邮件」回到原邮件 → 阅读面板显示任务 chip。
`data.test.ts` 覆盖 `listTasksForMessage`（只返回该邮件的任务、按创建时间倒序）。
