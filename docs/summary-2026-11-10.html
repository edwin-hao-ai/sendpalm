01多邮件账户：怎么合并、怎么切换

你最初的问题是这两个。答案分两半：合并本来就是默认的，切换以前根本没有。

合并：不需要做任何事

所有邮箱的邮件都写在同一张表里，每封邮件带一个「账户 id」。所以合并是默认状态， 同一个人给你工作邮箱和个人邮箱各发一封，列表里也是一组。

切换：以前不存在，现在有三种粒度

  • 全部账户（默认）—— 合并视图，不加任何过滤，就是原来的行为。
  • 单个邮箱 —— 列表上方一排标签：「全部账户 / 工作 / 私人…」，每个带未读数，点一下就只看这个邮箱。
  • 隔离账户 —— 账户设置里可选「并入全部账户」或「单独查看」。选后者的邮箱不进合并视图， 只有切过去才看得见（比如工作邮箱不混进私人收件箱）。

另外：合并视图里每行带一个彩色首字母圆点标明来源（新账户会从调色板轮流取色， 以前所有账户都是同一个绿色，根本分不出来），侧栏未读数也跟着当前选的邮箱走。

顺带补的两件「结构性」工作

1. 黑屏有了兜底。以前任何渲染异常都会让窗口变空，兜底是用全屏黑块盖住整个 App—— 等于同一个黑屏加一段堆栈。现在：出错只替换出错的视图，侧栏顶栏照常可用， 给「重试 / 重新载入 / 技术详情」，异常同时进错误日志。启动完成后的运行期错误只出一条可关闭的提示条， 不再盖住界面。

2. 加载态和错误态补齐。面板、浮层、设置分区以前是「加载中空白、失败也空白」， 看起来和「这条记录没有内容」一模一样。现在统一走一个面板级状态组件（骨架 / 带重试的错误 / 空态）， 并且有一条测试守着 23 个资源消费方，防止以后回退。

03性能：两个真正的瓶颈

3.1 首屏体积

第一次打包时，入口 JS 是 583 kB（gzip 177 kB）——因为详情面板、撰写窗口、命令面板、 新手引导全都塞在首屏里，哪怕用户只想看一眼收件箱。

chunk改前改后
入口583 kB / 177 kB gz272 kB / 90 kB gz
详情面板在入口内首次打开时加载（125 kB）
撰写窗口在入口内首次撰写时加载（35 kB）
命令面板在入口内首次 ⌘K 时加载（27 kB）

打包产物冷启动实测：首屏 108 ms，传输约 109 kB。

3.2 十万封邮件（之前没测过）

写了一个 10 万封邮件的压测，量了所有列表和搜索用到的查询。发现两个悬崖：

查询修前修后
首屏第一页72 ms4 ms
翻到第 500 页（「加载更多」）17,272 ms0 ms
稍后回复 / 搁置 / 提醒 计数705 ms0 ms
侧栏未读—6 ms
30 天未读—17 ms
每个账户的徽章—12 ms
中文三字搜索—506 ms
单封邮件详情—0 ms

原因和解法：「加载更多」用的是 OFFSET，数据库必须一行行跳过前面的记录（所以越翻越慢）； 改成用「上一页最后一封」当游标。三个 pile 计数用了一条 OR 查询，把索引全废了； 拆成三条窄查询。另外补了几个列表/计数索引。

正确性也验了：用游标翻完 10 万封，正好 100,000 条、不重不漏。

04iOS 黑屏：三个 bug 叠在一起

这个挂了好几天的「窗口全黑」，其实和 webview 一点关系都没有——进程根本没活过一秒。

① 启动入口的注解挂到了别的函数上

拆分代码时，一段注释被插在「启动入口」的注解和函数之间，注解于是绑到了旁边那个函数上。 结果 iOS 启动时调用的是「装加密库」的函数，装完就返回，进程立刻退出—— 系统日志写得很清楚：Process exited … | voluntary（主动退出，不是崩溃）。 桌面版从main直接调用，所以永远不暴露。

② 数据库迁移顺序错了（所有平台都会中招）

迁移是按「列表顺序」执行的，而列表后半段是倒着追加的。全新数据库上， 「回填字段」跑在了「加字段」前面，直接报错退出。 老用户因为迁移已记录会跳过，所以这是一个「只有新用户才会撞」的首次安装失败。

③ 后台任务抢在建表之前

MCP 网关和同步循环在窗口打开前就启动，比数据库建表还早，报 no such table。 现在两者都先等表出现。

验证：iPhone 17 模拟器里启动 → 新手引导 → 收件箱，截图在 docs/ios-screenshots/。 另外补了一个 verify-ios.sh 脚本（文档里引用了几周，但仓库里其实没有）， 它会在进程已经退出时直接报错——缺的正是这一步检查。

级别做了什么

拒付 → 0 条 拒付 → 命中， Re: 报价 → 报错 Re: 报价 → 正常。
顺带发现测试用的模拟数据库根本没实现这个查询——以前所有搜索测试都是假绿。
P0 连接邮箱真的连一次：保存后立刻跑一轮收信，按结果分三种处理—— 密码错就撤销这个账户并就地报错（带服务商提示），网络问题保留账户并告知会自动重试。
P1 富文本撰写：粗体 / 斜体 / 链接 / 项目符号。发出去时渲染两份—— HTML 收件人看到格式，纯文本收件人看到去掉标记的同一段话（不会收到 **urgent**）。
P1 撤销发送：点发送后先扣 5 秒，期间可以撤销并把正文带回撰写窗口； 就算这时退出应用，草稿也还在，不会丢。
P1 修了一个真 bug：收件人输入框失焦时不提交。表现为—— 「打好地址直接点发送」，按钮是禁用的、点了没反应，可输入框里明明显示着地址。
P1 多选扩展到所有列表：报刊 / 单据 / 回收站 / 垃圾邮件都能勾选， 批量条（稍后回复 / 归档 / 删除）抽成全局组件。
P1 日历键盘导航：←/→ 一天（周视图一周、年视图一月）、↑/↓ 一周、Enter 打开当天第一场。
P2 密度三档（紧凑/标准/舒适）、强调色 5 选、打印样式（⌘P 打当前这封）、 通知声音开关、筛选台决定沉淀为规则（「以后这个发件人都这样」）。
